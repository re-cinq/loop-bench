# Call onError for a rejection that is not an Error

Issue: re-cinq/HALEngine#95
Labels: priority:medium, type:bug, size:S, area:api

## Why

The orchestrator's `catch` gates `onError` on `error instanceof Error`. A rejection that is not an `Error` — a thrown string, a plain object, a value from a library that rejects with its own shape — bypasses `onError` entirely while still propagating to the caller.

`onError` is the seam a deployer uses to count failures, page someone, or write an incident record. A gate that silently drops a class of failures makes it a liar in exactly the cases nobody tested for, and the deployer's dashboard reads "no errors" while the caller sees rejections.

Recorded as measured behaviour in `specs/hal-engine-config-hooks/spec.md` by HALEngine#83, which scoped itself to specifying the seam rather than changing it, and raised again by the reviewer on that PR. The spec notes this property is owned by no issue in the epic; this is that issue.

## What to do

Call `onError` for every rejection. Whatever is not already an `Error` gets wrapped in one, preserving the original as the `cause`, so a hook typed against `Error` keeps compiling and a hook that wants the raw value can still reach it. The re-thrown value at the caller boundary stays exactly what it is today, so nothing downstream changes shape.

## Acceptance criteria

- [ ] A provider rejecting with a string calls `onError` once, with an `Error` whose `cause` is that string, and the caller still receives the original rejection unchanged
- [ ] The same holds for a rejection with a plain object and with `undefined`
- [ ] A rejection that is already an `Error` reaches `onError` as the same instance, not a wrapper, pinned by the existing tests remaining unedited
- [ ] `specs/hal-engine-config-hooks/spec.md` replaces its recorded-flaw line with the new guarantee, and the CHANGELOG says what changes for an existing consumer
- [ ] `npm run build`, `npm test`, `npm run typecheck`, `npm run eslint` (`--max-warnings 0`) and `npm run prettier:check` pass
